# Permissioned spaces: current contract

The October transport targets reference implementation `5b95b2f2723a2882824fbb0b819fd6aad884ef20` and alpha PDS `79d6307e19908f3af406838ea0e5fae42847f182`. The sandbox pins the alpha PDS source and checks its Dockerfile and lockfile hashes before building. These are separate snapshots. The deployed PDS image must also be traced to its source revision and immutable image digest; a source checkout alone does not prove what is running.

| Concern              | Stratos custody                                                           | PDS custody                                                                    |
| -------------------- | ------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| Space authority      | Stratos                                                                   | Stratos                                                                        |
| Repository host      | Stratos                                                                   | Member's spaces-capable PDS                                                    |
| Commit signer        | Stratos's per-actor P-256 key, attested by Stratos enrollment             | Account key held by the member's PDS                                           |
| Authorization server | The issuer accepted by the OAuth flow; it need not be the repository host | The issuer accepted by the OAuth flow; it need not be the repository host      |
| Record source        | Stratos's signed MST repository                                           | Member's upstream space repository                                             |
| Membership decision  | Current Stratos enrollment                                                | Current Stratos enrollment selects which member repositories the Feedgen reads |

Space record URIs have the form `at://{authorityDid}/space/{type}/{skey}/{authorDid}/{collection}/{rkey}`. The authority DID is first; the author DID is not. A PDS can store a record claiming any Stratos boundary, so the Feedgen re-derives that boundary from authority enrollment before admitting it. Membership selects repositories to read; it does not prevent a removed member from writing on their own PDS.

Stratos currently exposes `zone.stratos.space.*` authority endpoints, including `getSpaceCredential`, `getRecord`, `listBlobs`, and `listRepos`, plus `zone.stratos.sync.*` pull reads. These are deliberately separate from the upstream `com.atproto.space.*` namespace. The alpha PDS hosts member repositories using upstream `com.atproto.space.*` methods. Stratos's custom credential mint accepts a PDS-issued delegation as `Authorization: Bearer` with a standalone DPoP proof and a JSON `space` body; the internal body-delegation transport remains supported. Stratos does not advertise the upstream `#atproto_space_host` role or claim complete upstream authority discovery.

The custom `zone.stratos.space.listRepos` enumerates active boundary enrollments, not standard writer updates. Its cursor is a member DID and appears only for full pages. The Rust membership reconciler completes that snapshot before replacement. Standard `com.atproto.space.listRepos` uses exclusive space-revision cursors, permits repeated writers, and requires continuation until an empty page. Never use a writer delta to revoke omitted members. See the proposed [October writer-sync contract](./october-writer-sync-contract.md); no standard writer handlers are enabled by that design.

The standard receiver (Plan 014, PR #218) coexists with legacy OAuth/DPoP clients. The Rust Feedgen exchanges its existing service delegation in Bearer Authorization with an HTTP signature and a JSON `space` body. Standard credentials bind `cnf.kid` to a fresh grant-owned P-256 `did:key`, default to 600 seconds, and cannot exceed 3,600 seconds. Reads sign Authorization and Atproto-Space-Audience: the repo owner DID for repo operations, or the authority DID for membership listing. Signatures can be reused for that audience until expiry; methods, URLs, hosts, and service fragments are not read audiences. Legacy credentials retain their separate `cnf.jkt`/DPoP transport. A credential's space scope maps to one Stratos boundary; it is not the original member's live identity. Removing that member prevents new credentials and service-member requests that consult current enrollment, but an already-issued credential can still read that space until expiry. Wrong-key proofs and expired credentials fail. A local catalog boundary deletion or revision change invalidates credentials bound to the old revision on Stratos endpoints. Foreign PDS hosts do not understand Stratos's private boundary revision claim, so local revision invalidation is not a universal remote revocation signal.

For the Feedgen, authority membership must also fence work already in flight: a generation change must prevent staged foreign commits from being promoted after removal and must survive restart. This is a separate ingestion control, not credential revocation. Deployments without that generation fence retain an in-flight exposure window. Outstanding foreign-host credentials remain bounded by their expiry unless the foreign host provides an independent revocation mechanism.

Signing has two different meanings here. Stratos-custody MST commits and PDS-custody account commits can authenticate a signer and the relevant committed state. The current cross-host space proof uses a signature/MAC over a served view; it does not establish a durable, independently verifiable full-content proof for every historical record. Do not equate a valid credential or signed response with proof that the host returned all permitted content. The remaining work is interoperable authority discovery, foreign-host revocation, and a complete content-proof contract.

The October client contract is pinned to upstream implementation `5b95b2f2723a2882824fbb0b819fd6aad884ef20`. This is not a deployed-version attestation. The Rust client has no legacy fallback; coordinate receiver/client restart and discard old grants. The AiaB primary PDS now uses the October source pin. Runtime acceptance still requires separate reviews and a clean candidate commit. The `rust-production-interop` suite adds a second owner's publication and Rust ingestion on the same primary PDS after the mandatory ten-assertion baseline; the separate `standard-credential-transport` suite retains its transport denial and reuse checks. The combined `october-interop` suite requires all fifteen standard assertions and eleven Rust assertions after baseline. It uses distinct standard and Rust fixture accounts. It first verifies the default 600-second lifetime, then recreates only the disposable authority with a ten-second lifetime for actual Rust expiry refresh. Separate regression runs use fresh sandbox accounts. The independent PR #217 DPoP ADR is not required for this transport.

Early revocation fanout is optional, not an automatic consequence of member removal. Plan 017 is not included or deployed by this change. This repository candidate is not evidence of any production deployment. Custom membership enumeration selects repositories independently of upstream writer metadata; it does not establish full standard authority support. See the [operator rollout and rollback procedure](../operator/configuration.md#october-spaces-rollout).

The Plan 016 caller inventory found no actual `com.atproto.space.listSpaces` or `com.atproto.space.createSpace` requests in production packages, Clubhouse, or tests. No request-field rename or dependency upgrade is needed. Internal space types and OAuth scope syntax remain unchanged. The installed service validator, `@atproto/lexicon` 0.7.11, accepts a `space-ref` schema but also accepts an invalid space string: it does not enforce that format. The executable `test/spaces-alignment/scenarios/installed-validator.test.ts` regression loads the service-installed package, checks its version, and verifies valid and malformed strings without normalization. It also confirms that runtime `parseSpaceUri` rejects the malformed strings. Keep custom lexicon references as plain strings and retain runtime `parseSpaceUri` validation. A future schema-only follow-up must first verify malformed-value rejection in the selected validator, then update the affected lexicons and regenerate bindings within its own scope.
